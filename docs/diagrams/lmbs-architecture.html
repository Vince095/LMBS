🛡 Cross-cutting Security & Controls

Identity & access
  • JWT + RBAC on every API route
  • bcrypt password hashing
  • wallet challenge–signature binding
  • on-chain RBAC via RoleAuthority
  • separation of duties between institutions
Transaction integrity
  • EIP-712 votes: nonce, deadline, chain id
  • tx receipts and events verified server-side
  • signing keys stay in the user's wallet
  • Besu node + account allowlists
Data protection
  • AES-256-GCM documents; only the hash goes on-chain
  • helmet headers, CORS allowlist; rate limiting on login and sign-up
  • audit log of state-changing requests (secrets redacted)

Registration flow

  1. 1Applicant uploads documents; backend encrypts them and returns the keccak256 hash
  2. 2Applicant signs submitRegistration in their own wallet
  3. 3Backend verifies the receipt and RequestSubmitted event
  4. 4Institutions approve (transaction or signed EIP-712 vote)
  5. 5execute() checks identity, disputes and encumbrances, then mints the ERC-721 title
  6. 6Indexer projects the events into MongoDB read models
  7. 7Certificate is verified against ownerOf() on-chain

Planned / out of scope

  • W3C verifiable credentials and DIDs
  • BBS+ selective disclosure, zero-knowledge proofs
  • KMS / HSM key management and key rotation
  • MongoDB client-side field encryption
  • live email / SMS gateways
  • GIS and cadastral system integration
